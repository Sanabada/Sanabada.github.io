Cloud-Native POC + Scale & Support on HANA Cloud

Delivered features for a globally used HANA Cloud product and improved its scalability/diagnostics. Built a Kyma/Kubernetes proof-of-concept to simplify cloud-native development and operations, and handled post-production hotfixes.

What I shipped

  • Product delivery: engineered a solution for the auto industry (engineering task automation + shift scheduling), deployed globally on AWS HANA Cloud.
  • Scale + operability: improved product scalability and enhanced diagnostics/upkeep so it was easier to run in production.
  • Cloud-native POC: led a Kyma proof-of-concept using Kubernetes + Docker to simplify cloud-native app development and operational traceability.
  • Post-prod response: rolled out hotfixes, ensured system health, and supported customers via ServiceNow and Splunk.

Stack snapshot

Kyma Kubernetes Docker Spring Boot REST APIs GraphQL HANA Cloud Splunk ServiceNow

Public context (high-level)

Kyma is SAP’s Kubernetes-based runtime environment concept for cloud-native extensions and services. This is why the POC was practical: it reduced operational friction and aligned with a managed K8s runtime model.

Public reference: SAP Kyma environment overview.
help.sap.com

Engineering decisions I’m proud of

  • Operational-first engineering: features are only “done” when they are observable and supportable.
  • Pragmatic Kubernetes adoption: POC focused on deployability and traceability—not “K8s for K8s’ sake”.
  • Fast incident loops: reduced detection → diagnosis → fix → verification time with Splunk + disciplined hotfix workflows.

What I can share publicly

This case study is intentionally public-safe: no customer data, no internal architecture diagrams, and no proprietary flows. The focus is on engineering outcomes—scalability, diagnostics, cloud-native patterns, and production support discipline.
