FCM APIs, Test Automation, and Azure Readiness

Owned backend reliability and release confidence for an FCM (Future Commission Merchant) web application: Spring MVC APIs, Selenium/TestNG automation, and migration readiness for Azure with Docker.

What I shipped

    • Built and owned Java/Spring services and REST APIs for the FCM (Futures Commission Merchant) platform, enabling futures & options workflows across trade capture → clearing/allocations → positions/margin/risk; improved latency, correctness, and auditability via stronger instrumentation and structured logging.
    • Hardened EOD margin/risk/positions processing by automating and standardizing AutoSys job chains on Linux/Unix (dependencies, retries, alerts, runbooks), reducing manual intervention and improving run consistency for risk-sensitive back-office cycles.
    • Built an agentic AI ops copilot (LLM + RAG) over runbooks + Splunk + ServiceNow + AutoSys metadata to triage breaks and recommend next actions with human-in-the-loop approvals; reduced incident investigation time and improved on-call handoffs.
    • Optimized SQL stored procedures supporting core processing modules, delivering ~30% performance improvement and improved edge-case correctness through query tuning and validation.
    • Built/maintained Java/Spring microservices with reliability focus; created a Selenium + TestNG automation framework reducing regression cycle time; supported cloud migration and containerization (Azure/Docker) for scalability.

Stack snapshot

Azure Spring Boot / Spring MVC REST APIs Docker SQL + Stored Procedures Selenium TestNG JUnit Jenkins pipeline Unix servers ServiceNow

Operating constraints (public-safe)

In markets-adjacent systems, reliability and audit-friendly operations matter: releases need repeatable testing, predictable deployments, and fast diagnosis paths in production.

Engineering decisions I’m proud of

  • Testing discipline as a product feature: automation wasn’t optional—regression reliability enabled faster, safer releases.
  • Operational clarity: stronger logs + repeatable troubleshooting reduced time-to-diagnosis in post-prod incidents.
  • Cloud readiness without a rewrite: dockerization and deployment hygiene improved scalability while keeping change risk controlled.

What I can share publicly

This case study intentionally stays high-level (no proprietary endpoints, data, or business logic). The focus is on engineering practices: reliability, automation strategy, release ownership, and cloud migration readiness.
